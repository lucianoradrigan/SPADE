# dc_motor forecast-residual anomaly detector (E14)

## Design change declared (2026-10-21): steady-state gate on the residual threshold

**This change was decided after seeing E14 test results.** The first evaluation (`dc_motor_residual_anomaly.md`, runs `*_run01`) showed that start-up windows inflated the threshold: thresholds of 273 and 96, about 50 % detection at AUROC 1.000 (AI-N18). The steps followed the user's instruction of 2026-10-21.

1. **Gate fixed from physics before refitting, with no data at all.** The gate is `ai/residual.steady_state_gate_s`:
   - **Parameters:** nameplate values of `datagen.runner.build_plant`: J = 0.0275 kg·m², r_a = 16 mΩ, ψ_e = 0.165 Wb, usable current 0.8 × 210 A, load a + b·ω with a = 0.01 N·m and b = 0.05 N·m·s.
   - **Slew:** current-limited acceleration from rest to 250 rad/s, the highest speed evaluated in E14: t_slew = 330 ms.
   - **Settling:** 5 τ_m, with τ_m = J·r_a/ψ_e² = 16.2 ms.
   - **Result:** **gate_s = 411 ms**.
   - **Rule:** a window is scored only if it starts ≥ gate_s after the last speed-reference change. The start of a run counts as a reference change.
2. **Threshold recomputed on healthy validation windows that pass the gate.** The 99th percentile and the per-channel median scale were recomputed only on the healthy validation runs recorded in `*_run01/metrics.json["val_groups"]`, using only windows that pass the gate. Command: `python experiments/refit_residual_gate.py --run <run01>`. The forecaster weights are unchanged; the new runs `*_run02` are copies with only `residual_detector` refitted. No faulted window was used.
3. **Re-evaluated once on the test conditions.** The test conditions are the held-out conditions of the same cache, and this report is that single run. Around a reference step, windows inside the gate are not scored. The step false-alarm rate counts windows that start in the 0.3 s after the gate ends.
4. **What did not change:** criteria and targets, held-out conditions, models, quantile, and the edge tiers (not refitted, not promoted).

Generated by `python experiments/report_residual_anomaly.py --runs configs/regressors/dc_motor_residual_pc/2026-10-21_run02 configs/regressors/dc_motor_residual_pc_novv/2026-10-21_run02 --cache ../SPADE-dev/data/eval_cache_5class.parquet --custom-cache ../SPADE-dev/data/ood_eval_cache_custom.parquet --stem dc_motor_residual_gate --preface /tmp/claude-1000/-home-seven-post-doc-plataform-proposed-SPADE/dea37e0e-9a5a-4fc4-b6d6-a76d8649ae03/scratchpad/gate_preface.md` on 2026-10-21 (Linux x86_64, Python 3.12.13). Raw values: [`dc_motor_residual_gate.json`](dc_motor_residual_gate.json).

Simulated windows only. Every number below is measured on simulated windows of conditions excluded from training. The seed only changes the vibration channels, so the four seeds of a noise-free condition give identical current/rpm windows (AUDIT_ANSWERS Q15).

## Design (fixed before looking at faulted windows)

- Highest fault frequency evaluated: **196.1 Hz** (inner race at 250 rad/s); half period **25.5 samples** at 10 kHz. Horizon **16 samples** (1.6 ms). No decimation (the 4th ripple harmonic, 785 Hz, is far below the 5 kHz Nyquist).
- Per-speed fault frequencies (Hz): see the JSON (`design.fault_frequencies_hz`).
- Score: mean over current_r and rpm of RMSE(physical residual over the horizon) / median healthy-validation RMSE. Threshold: 99th percentile of healthy validation scores.

## Variant selection and promotion

- **Rule:** fixed on 2026-10-21. The variant is chosen on criteria 1 and 3 only (healthy data). If both qualify, the one without voltage_v wins.
- **Criterion 1:** both variants pass.
- **Criterion 3:** both **fail**. False alarms on healthy windows at 100 % noise: **58.3 %** with voltage_v, **71.2 %** without. Every other held-out condition: 0 %.
- **Selection:** neither variant qualifies, so the rule selects none and the tie-break does not apply. AUROC was not used.
- **Promotion: not done.** The condition was that criteria 1–3 still hold with the new threshold; criterion 3 fails (AI-N21). The registry is unchanged.
- **No retuning:** the threshold was not retuned after this evaluation. Changing the gate, the quantile or the noise handling now would be tuning on the test conditions.
- **What the gate did fix:** at ×1 severity, detection is 100 % instead of ≈ 50 % (AI-N18's cause).
- **What it costs:** the threshold is now tight enough that sensor noise at the top of the range crosses it.
- **Hypothesis, not verified:** the per-channel median scale and the 99th percentile come from validation runs with noise drawn between 0 and ≈ 99 %, mostly well below 100 %.
- **Start-up and steps (criterion 5, reported):** start-up windows are no longer scored by design. The table's 80.6 % / 75.8 % is the share that *would* cross the threshold, which is why the gate is needed. After a reference step, windows starting in the 0.3 s after the gate flag 33.3 % (n = 33): residual transient beyond the 411 ms gate.
