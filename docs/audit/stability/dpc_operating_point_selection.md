# C1, option 1: DPC v3/v4 selected by operating point

Generated by `python experiments/dpc_operating_point_selection.py`; raw values in [`dpc_operating_point_selection.json`](dpc_operating_point_selection.json). No network was retrained; `control/dpc/controller.py::ScheduledDpcController` picks v3 inside a region of (R, |v_ref|) and v4 outside it, with 5 % hysteresis on the boundaries. **The default controller is unchanged** (v4); switching it needs confirmation.

## Region (chosen on the design grid only)

- Band: R ∈ [7.25, 8.75] Ω and |v_ref| ≤ 62.5 V; small references: |v_ref| ≤ 10.0 V for R ∈ [5.0, 12.0] Ω.
- Design grid: R = 5, 6, 7, 7.5, 8.0064, 8.5, 9, 10, 12 Ω × |v_ref| = 10, 25, 35, 50, 75, 100 V (v3 and v4 settled RMSE, in the JSON). Each boundary lies halfway between the last design level where v3 beat v4 and the first where it lost.
- **Declared iteration.** A first rule put the boundaries on the winning design levels (7.5–8.5 Ω, ≤ 50 V). Its load-step run showed that with hysteresis the controller never re-entered the band at the nominal 50 V (the operating point sat exactly on the boundary), so it stayed on v4 after the load returned to 8 Ω. The rule was revised with the halfway principle above, using the design grid only; the evaluation points below were not used to choose it.
